## 2. Problem

`TASK_0104` established the state-based-action seam and a minimal set scoped to the current card pool: player loss at 0 life (704.5a), creature with 0 toughness to the graveyard (704.5c), and creature with lethal damage destroyed (704.5g). As the pool grows with instants, sorceries, and triggered abilities, the remaining Rule 704.5 checks become reachable. This task expands the checklist inside the existing seam — it does NOT touch the priority loop's structure (that boundary is fixed by ADR-012).

## 3. Acceptance Criteria

- [ ] A player who attempted to draw from an empty library loses the game (Rule 704.5c — draw-from-empty flagged on the failed draw)
- [ ] A player with 10 or more poison counters loses the game (Rule 704.5c) — model only if a poison source is in the pool; otherwise wire the check and leave untriggered
- [ ] A creature with toughness 0 or less is put into its owner's graveyard (Rule 704.5f), correctly distinguished from destruction (matters for indestructible, `TASK_0506`)
- [ ] A creature dealt lethal damage by a deathtouch source is destroyed (Rule 704.5h) — coordinates with deathtouch (`TASK_0206`)
- [ ] The legend rule: a player controlling two or more legendary permanents with the same name chooses one to keep, the rest to the graveyard (Rule 704.5j)
- [ ] Aura attached to an illegal object or nothing goes to the graveyard (Rule 704.5m); a token that has left the battlefield ceases to exist (Rule 704.5d)
- [ ] All applicable SBAs are performed simultaneously in a single check, and the check repeats until no SBAs are performed (Rule 704.3) before triggers are put on the stack
- [ ] Unit test: draw from empty library → that player loses
- [ ] Unit test: -X/-X reduces a creature to 0 toughness → graveyard (not "destroyed")
- [ ] Unit test: two same-name legends → one kept, one to graveyard

## 4. Implementation Guidance

- Locate the SBA checker seam introduced in `TASK_0104` (the `PROCESSING_SBAS` state's checker). Add the additional 704.5 checks to that single checker — do not add SBA logic anywhere else in the loop.
- Preserve the "check all, apply simultaneously, repeat until stable" contract (Rule 704.3). The repeat loop already exists from `TASK_0104`; this task only lengthens the checklist it runs.
- Order relative to triggers is fixed by the 117.5 procedure: SBAs loop to stable, then `TASK_0401` triggers go on the stack, then repeat.
- Only implement checks the pool can actually reach; for checks needing an absent card type (poison), wire the predicate but expect it dormant. Note this in the test file so future card additions know the hook exists.
- Key rules: RX-704.3, RX-704.5c, RX-704.5d, RX-704.5f, RX-704.5h, RX-704.5j, RX-704.5m.
