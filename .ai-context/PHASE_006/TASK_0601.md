## 2. Problem

RNG is seeded from the wall clock in three places — `RandomGenerator` default constructor (`DateTime.UtcNow.Ticks`), the `Default` static (`Environment.TickCount`), and `ExperimentSimulator` — so runs are not reproducible. Worse, a single shared `IRandomGenerator` is drawn by both the engine (shuffle, play/draw roll) and every strategy. That coupling means adding one engine draw shifts every later strategy draw, and "same board, different AI" experiments (the AI phase) are impossible. This task establishes one recorded master seed split into independent sub-streams.

## 3. Acceptance Criteria

- [ ] The per-game seed derived in `TASK_0101` (from `ExperimentConfig`) is threaded onto `GameConfig` as the game's master seed, so a single game is self-describing and replayable in isolation; when unset it is auto-generated once and always recorded
- [ ] A deterministic derivation (SplitMix64-style) produces independent sub-stream seeds from the master
- [ ] Distinct `IRandomGenerator` instances exist per stream: one engine stream, one per player strategy
- [ ] A recording (tee) `IRandomGenerator` decorator logs each draw with its stream identifier so decision-log replay (`TASK_0804`) can reconstruct draws — opt-in, off on normal runs
- [ ] The wall-clock constructor and `Default` paths are removed or gated so no logic path pulls a time seed
- [ ] Adding an engine draw does not perturb any strategy stream (independence test)
- [ ] A sequence-stability test asserts the same master seed reproduces an identical draw sequence across runs
- [ ] Mana spend and auto-selection over `ManaBlob`/`IManaPool` uses a fixed canonical mana ordering (not dictionary iteration order), so the same master seed yields an identical mana-spend sequence — a determinism fix, not an RNG stream
- [ ] Existing tests pass

## 4. Implementation Guidance

- Seam with `TASK_0101`: `TASK_0101` (Phase 1) already puts a master seed on `ExperimentConfig` and derives a unique per-game seed. This task threads that per-game seed onto `GameConfig` and splits it — do not re-derive the per-game seed here.
- Add a small SplitMix64 derivation (pure, roughly ten lines): given `(master, streamId)` return a stream seed.
- The infrastructure factory that today injects one `IRandomGenerator` should mint per-stream generators; `EntityFactory.CreatePlayer` wires each strategy with its own derived stream.
- Add a recording (tee) `IRandomGenerator` decorator that forwards to the real generator and logs `(streamId, value)` per draw into the event stream; this is the capture mechanism for `TASK_0804`'s playback generator. Keep it opt-in so normal runs pay nothing.
- Keep the API minimal — a named stream identifier is enough.
- Do NOT build per-rollout RNG here — that is `TASK_0602` (clone), which reuses this derivation.
- ManaBlob nondeterminism caveat: `ManaBlob`/`IManaPool` back mana amounts with a dictionary keyed by mana type; `Pay`/`CanPay` iterate it both to spend and to auto-select which mana satisfies a generic cost. .NET dictionary enumeration order is not contractually stable, so two runs on the same master seed can spend mana in a different order — perturbing the event stream and the `TASK_0803` validation hash with no RNG draw involved. ADR-016's audit found only the three wall-clock seed sources and did not cover this. Pin a canonical mana-symbol ordering (e.g. WUBRG → generic → colorless) for both spend selection and enumeration. This is an ordering fix, not an RNG concern — do NOT route it through the split streams.
