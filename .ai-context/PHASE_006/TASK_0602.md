## 2. Problem

Information Set Monte Carlo Tree Search (the AI phase) runs thousands of rollouts per decision, each needing an independent mutable copy of the current position. No clone infrastructure exists. This task lands a correct deep-clone seam on the tabletop; performance tuning (copy-on-write or journal-undo) is deferred to the AI phase after profiling real search load. Because ISMCTS searches under hidden information, the same seam must also produce a *determinized* copy — one where cards the searching player cannot see (opponent hand, library order, face-down permanents) are replaced by a sampled arrangement consistent with public information — so masking is a property of how state is forked here, not a strategy-layer concern.

## 3. Acceptance Criteria

- [ ] The tabletop exposes a deep clone that returns a fully independent copy
- [ ] Mutable state is deep-copied: players, zones and their entity lists, permanents (tapped state, part lookup), the mana blob dictionary, per-turn decisions, and tabletop scalars
- [ ] Immutable data is shared by reference: cards, abilities, costs, effects, deck definitions
- [ ] Permanent owner and controller back-references are remapped by identity (clone players first, then remap) — no cycles, no cross-links to the original graph
- [ ] Mutating a clone never affects the original (isolation test across zones, life, tap state, mana)
- [ ] A cloned tabletop draws from its own derived RNG stream (master seed plus node path), never the live stream
- [ ] A cloned player does NOT deep-copy the real strategy — the rollout installs its own policy into the strategy slot; the clone binds the derived rollout RNG, never the live stream
- [ ] The clone accepts an optional determinization: cards hidden from the cloning player (opponent hand, library order, face-down permanents) are replaced by a sampled arrangement consistent with public information, drawn from the clone's derived RNG stream
- [ ] Both forms are produced through the one seam — a perfect-information clone (used by the WPF "fork this position" debugger) and a determinized clone (used by ISMCTS); the perfect-information clone is the default when no determinization is requested
- [ ] Existing tests pass

## 4. Implementation Guidance

- Clone order: players first into an identity map, then zones and permanents remapping owner and controller references via the map; finally tabletop-level references (active, non-active, prioritized players) point at the cloned players.
- Cards, abilities, costs, and effects are init-only immutable — share them, do not copy.
- The mana blob and the zone collection need explicit value-copies of their internal collections.
- Do NOT build copy-on-write or journal-undo here — deep clone is the correctness baseline; performance is an AI-phase task after profiling.
- The per-rollout RNG derivation reuses the SplitMix64 helper from `TASK_0601`.
- The audit flagged the `Player → Strategy → RNG` chain: do NOT clone the real strategy. Leave the strategy slot for the rollout policy to fill and inject the derived rollout RNG. Cloning the live strategy would both share the live stream and defeat the purpose of an independent rollout.
- Note the existing "create a copy of tabletop with appropriate visibility" TODO in `GameJudge` combat steps — this seam also serves that visibility-copy need.
- Determinization builds on the plain clone: clone first, then reshuffle the hidden zones (opponent hand and library, face-down permanents) from the searching player's point of view using the clone's derived RNG stream, keeping the count and any publicly-known constraints fixed. Model it as an optional argument or a separate `CloneDeterminized(perspectivePlayer)` entry point so the perfect-information clone stays the zero-cost default.
