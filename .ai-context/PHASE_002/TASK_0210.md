## 2. Problem

Any single creature can currently block an attacker. Menace (Rule 702.111) requires that the attacking creature be blocked by two or more creatures or not at all. This changes blocking combinatorics — the defender must commit multiple resources or let the creature through.

## 3. Acceptance Criteria

- [ ] A creature with menace cannot be blocked by a single creature
- [ ] A creature with menace can be blocked by two or more creatures together
- [ ] A creature with menace is unblocked if the defender cannot assign 2+ blockers
- [ ] Block validation rejects single-blocker assignments against menace creatures
- [ ] Evasion stacking: flying + menace = must be blocked by 2+ creatures that each have flying or reach
- [ ] `IStrategy.DecideBlockers()` only receives legal combinations (respecting menace constraint)
- [ ] Unit test: menace creature vs 1 available blocker — cannot be blocked
- [ ] Unit test: menace creature vs 2+ available blockers — legal block with 2+

## 4. Implementation Guidance

- Extend the `BlockingValidator` (from TASK_0202) to enforce minimum blocker count
- Menace check: if attacker has menace, the set of blockers assigned to it must have size >= 2
- This is a constraint on the blocking assignment as a whole, not individual blocker legality
- Consider how `IStrategy` enumerates valid blocking assignments — menace increases combinatorial space
- For `RandomStrategy`: if menace and < 2 valid blockers available for that attacker, don't block it
