## 2. Problem

Lethal damage is currently defined as damage >= toughness minus existing damage. Deathtouch (Rule 702.2) redefines lethal to 1 for damage assignment purposes. This interacts critically with trample: a 6/6 deathtouch trample only needs to assign 1 to each blocker, trampling the rest. Deathtouch also causes destruction via SBA Rule 704.5h (any nonzero damage from a deathtouch source = destroy).

## 3. Acceptance Criteria

- [ ] Any nonzero damage dealt by a source with deathtouch triggers destruction via SBA (Rule 704.5h)
- [ ] For damage assignment purposes (trample), lethal = 1 when attacker has deathtouch (Rule 702.2c)
- [ ] Deathtouch + trample combo: 6/6 blocked by 5/5 + 3/3 → assign 1+1, trample 4
- [ ] Deathtouch without trample: all damage still goes to blockers (no player damage)
- [ ] Deathtouch vs indestructible: damage is dealt but destruction is prevented (creature survives)
- [ ] Damage tracking: mark damage source as having deathtouch for SBA evaluation
- [ ] Unit test: 1/1 deathtouch blocks 5/5 — both die (1 deathtouch damage kills 5/5)
- [ ] Unit test: 6/6 deathtouch trample blocked by 3/3 + 3/3 — assign 1+1, trample 4

## 4. Implementation Guidance

- Modify damage-marking to track whether the source had deathtouch
- In SBA checks (Rule 704.5h): creature with any damage from a deathtouch source is destroyed
- In damage assignment validation (from TASK_0205): if attacker has deathtouch, `lethal(blocker) = 1`
- This interacts with indestructible (TASK_0506, Phase 5): indestructible prevents destruction, so deathtouch has no effect against it — but damage is still dealt (lifelink still triggers)
