## 2. Problem

Double strike (Rule 702.4) deals damage in both the first and second combat damage steps. TASK_0203 built the two-step framework but only handles first strike (first step only). Double strike reuses that framework but participates in both steps, creating unique edge cases around timing and creature removal.

## 3. Acceptance Criteria

- [ ] A creature with double strike deals damage in both combat damage steps
- [ ] Double strike triggers the two-step split (same as first strike presence)
- [ ] A double-striker killed in the first step does not deal damage in the second step
- [ ] Giving double strike after the first step: creature deals damage in the second step only
- [ ] Removing first strike after the first step: creature cannot deal in the second step (it already dealt in first)
- [ ] Unit test: 3/3 double strike vs 4/4 vanilla — 3 first step + 3 second step = 6 total, kills the 4/4
- [ ] Unit test: 2/2 double strike vs 3/3 vanilla — 2 first step (3/3 survives), 2 second step = 4 total, kills 3/3. Double-striker takes 3 in second step and dies.

## 4. Implementation Guidance

- In the first combat damage step, include creatures with double strike alongside first-strikers
- In the second step, include creatures with double strike alongside non-first-strikers
- Track which creatures already dealt damage in step 1 to handle the "removed first strike" edge case correctly
- Edge case: a creature that had neither first/double strike at the start of the first step but gains double strike between steps deals damage in the second step only
