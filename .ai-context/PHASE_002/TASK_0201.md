## 2. Problem

The engine has no representation for keyword abilities. `IPermanent` lacks a way to query whether a creature has flying, trample, etc. The ANTLR parser (`MagicCardKeyword.g4`) only handles basic land types and mana symbols — it cannot parse keyword ability lines from card oracle text. Per ADR-009, keyword recognition belongs in the ANTLR grammar (keywords are static abilities under Rule 702, sharing the oracle-text parsing domain). All subsequent Phase 2 tasks depend on this foundation.

## 3. Acceptance Criteria

- [ ] `KeywordAbility` enum exists with values: Flying, Reach, FirstStrike, DoubleStrike, Trample, Deathtouch, Lifelink, Haste, Vigilance, Menace, Defender, Indestructible
- [ ] `IPermanent` exposes a method to check for keyword presence (e.g., `HasKeyword(KeywordAbility)`)
- [ ] `IPermanent` exposes a way to add/remove keywords at runtime (for future grant/remove effects)
- [ ] ANTLR grammar (`MagicCardKeyword.g4`) recognizes keyword ability lines in card oracle text (per ADR-009)
- [ ] Card parsing pipeline populates keyword data on `DefinedBlob.Card`
- [ ] `EntityFactory` transfers parsed keywords onto constructed `IPermanent` instances
- [ ] Unit tests verify parsing of all 12 keywords from sample card text

## 4. Implementation Guidance

- Add `KeywordAbility` enum to `Kvasir.Contract`
- Add keyword collection to `IPermanent` (consider `HashSet<KeywordAbility>` backing)
- Extend `MagicCardKeyword.g4` with lexer tokens for each keyword (Flying, Reach, First Strike, etc.)
- Add a grammar rule matching keyword lines, including comma-separated lists ("First strike, trample") and reminder text in parentheses (ignored)
- Regenerate the ANTLR parser and wire keyword extraction into the parse pipeline
- Update `DefinedBlob.Ability` or add a `DefinedBlob.Keyword` to store parsed keywords
- Update `EntityFactory` to read keywords from definition and attach to permanent
- Keep it simple for now: boolean-flag keywords only. Parameterized keywords ("Protection from X", "Ward {2}") are a later grammar extension (per ADR-009), not this task
