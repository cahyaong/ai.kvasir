## 2. Problem

Attacking currently taps the creature (Rule 508.1f), making it unavailable to block on the opponent's turn. Vigilance (Rule 702.20) removes this cost, allowing a creature to attack without tapping. This affects the attack/defense tradeoff — vigilant creatures can attack freely without defensive liability.

## 3. Acceptance Criteria

- [ ] A creature with vigilance does not tap when declared as an attacker
- [ ] A creature without vigilance still taps when attacking (no regression)
- [ ] A vigilant creature that attacked is available to block on the opponent's next turn
- [ ] Unit test: vigilance creature attacks, remains untapped
- [ ] Unit test: non-vigilance creature attacks, becomes tapped

## 4. Implementation Guidance

- In the "declare attackers" step, the tap-on-attack logic should check for vigilance
- If attacker `HasKeyword(KeywordAbility.Vigilance)`, skip tapping
- This is a single conditional in the attack declaration handler
- Ensure the tapped/untapped state is properly reflected for subsequent blocking decisions
