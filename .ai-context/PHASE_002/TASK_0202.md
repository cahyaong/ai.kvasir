## 2. Problem

All creatures can currently block all attackers regardless of evasion abilities. Flying (Rule 702.9) restricts which creatures can block flyers, and reach (Rule 702.17) exists solely to bypass that restriction. These are the most impactful evasion keywords for AI blocking decisions.

## 3. Acceptance Criteria

- [ ] A creature with flying can only be blocked by creatures with flying or reach
- [ ] A creature without flying can be blocked normally (flying/reach on the blocker is irrelevant)
- [ ] Block legality validation rejects illegal blocking assignments
- [ ] `IStrategy.DecideBlockers()` receives only legal blocking options
- [ ] Evasion stacking: flying + menace (future) applies both constraints cumulatively
- [ ] Unit tests: flyer vs ground, flyer vs flyer, flyer vs reach, ground vs ground

## 4. Implementation Guidance

- Add a `CanBlock(IPermanent attacker, IPermanent blocker)` check in the combat blocking logic
- For flying: if attacker has flying, blocker must have flying OR reach
- Reach alone does nothing unless the attacker has flying
- This is a filter applied before presenting blocking choices to `IStrategy`
- Consider placing the legality check in a `BlockingValidator` or similar (reusable for menace later)
