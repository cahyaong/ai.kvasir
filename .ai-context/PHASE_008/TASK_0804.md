## 2. Problem

Seed-replay reproduces a game only when the engine and strategies are deterministic and unchanged. Decision-log replay feeds the recorded decision events back through playback shims, which is robust to strategy nondeterminism and enables branching — replay up to decision K, then hand control to a live strategy to explore a what-if line. The decision events already exist (`TASK_0801`); this task adds the playback shims and the branch point.

## 3. Acceptance Criteria

- [ ] A playback strategy returns recorded decisions in order, matched by request key, asserting on mismatch rather than silently garbling
- [ ] A playback random generator returns recorded RNG draws in order for its stream
- [ ] A game reconstructs identically from a decision log via the playback shims
- [ ] Branching is supported: replay to decision index K, then swap in a live strategy for the remainder
- [ ] Cross-engine-version decision-log replay is documented as best-effort; a request-key mismatch fails loudly with location
- [ ] Tests: full decision-log round-trip; branch-at-K produces a divergent-but-valid continuation

## 4. Implementation Guidance

- The playback strategy implements `IStrategy`; each decision call pops the next recorded decision and asserts its request key equals the engine's current request key.
- The playback random generator implements `IRandomGenerator`, replaying the recorded draw sequence for its stream.
- Branch point: a runner installs playback shims until index K, then substitutes the real strategy and a fresh derived RNG stream (from the master seed) for the post-branch tail.
- This depends on decisions being recorded by stable identity plus request key (`TASK_0801`) — no menu-index assumptions.
