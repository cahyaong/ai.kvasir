## 2. Problem

The card pool has only permanents (creatures, lands). There is no notion of instant-speed versus sorcery-speed casting. This task introduces the instant and sorcery card types and enforces the timing restrictions that gate when each type can be cast — the rule that makes "holding up an instant" a real decision and the core source of instant-speed interaction for the AI.

## 3. Acceptance Criteria

- [ ] Instant and Sorcery card types exist and parse through the ANTLR pipeline
- [ ] An instant can be cast any time its controller has priority (Rule 601.3e), including in response to another object on the stack
- [ ] A sorcery can be cast only during the controller's main phase, with an empty stack, on their own turn (Rule 307)
- [ ] The same timing gate applies to sorcery-speed permanents (creature/enchantment/artifact/planeswalker) — main phase, empty stack, own turn
- [ ] Timing legality is enforced when enumerating legal actions at a priority hold, not after the fact
- [ ] Casting an instant while the stack is non-empty places it above the object it responds to (Rule 117.7 / LIFO)
- [ ] Unit test: instant cast on opponent's turn is legal; sorcery cast on opponent's turn is rejected
- [ ] Unit test: sorcery cast with a non-empty stack is rejected

## 4. Implementation Guidance

- Add Instant and Sorcery to the card-type model. Confirm the ANTLR grammar / `MagicCardProcessor` maps these type lines (they may already be recognized as type strings — verify the enum/model covers them).
- Implement a timing predicate: `CanCastNow(card, tabletop, player)` returning whether the type's timing restriction is satisfied. Encode the Section 2.3 table from `DESIGN_Priority_Stack_And_Combat_Keywords.md`.
- Call this predicate from the priority loop's action enumeration so illegal-timing casts never surface as options.
- Add 2-3 canonical non-targeted instants/sorceries as YAML test cards now (hybrid card-pool model, ADR-010) — e.g., a "draw a card" instant, a "gain life" instant, a "each player draws" sorcery. Targeted spells wait for `TASK_0304`.
- Key rules: RX-307, RX-601.3e, RX-117.7.
