## 2. Problem

`GameJudge` has a `MUST` TODO: "Wire up the validation logic for executing combat phase!" Invalid attacking/blocking decisions are silently accepted or fall back to `None` without proper rules enforcement.

Specific gaps:
- No validation on the `AttackingDecision` returned by strategy (could contain tapped/sick creatures)
- Blocking assignments aren't validated (could block while tapped, assign one blocker to multiple attackers)
- Invalid entries should be filtered out (game continues with valid subset), not reject the entire decision

## 3. Acceptance Criteria

- [ ] `AttackingDecision.Validate()` rejects creatures that are tapped, have summoning sickness, or aren't controlled by active player
- [ ] `BlockingDecision.Validate()` rejects creatures that are tapped or aren't controlled by defending player
- [ ] A blocker cannot be assigned to multiple attackers
- [ ] Invalid individual creatures are removed from the decision (game continues with valid subset)
- [ ] Validation messages are included in `ExecutionResult`

## 4. Implementation Guidance

- `Validate()` methods already exist on `IAttackingDecision` and `IBlockingDecision` — expand them
- `GameJudge.ExecuteDeclaringAttackerStep()` has TODO: "Remove all invalid attacking creatures, and continue with the valid ones!"
- Same pattern for `ExecuteDeclaringBlockersStep()`
- Key rules: RX-508.1a (legal attackers), RX-509.1a (legal blockers)
