## 2. Problem

The engine has only `RandomStrategy`. This task lands the MCTS machinery as a
**perfect-information thin slice** first — the full tree/UCT/rollout loop wired
to the Id-stable deep clone (not yet the determinized clone), validated on a
fully-observable position. Proving the tree machinery in isolation removes a
whole class of bugs before determinization is layered on in `TASK_0702`. See
`DESIGN_AI_SearchStrategy.md` for the complete design.

Scope is priority-action decisions only (`PerformPrioritizedAction`); combat
nodes (`TASK_0703`) and determinization (`TASK_0702`) are separate tasks. The
agent must still play a full legal game by delegating non-searched callbacks to
a sane default (attack/block via the existing `RandomStrategy` helper, pass on
non-prioritized).

## 3. Acceptance Criteria

- [ ] `MctsNode` exists with `Parent`, `IncomingMove`, `Children` keyed by `MoveKey`, `VisitCount`, `TotalValue`, `AvailableCount`, `MeanValue`
- [ ] `MoveKey` (readonly record struct: `MoveCategory` + canonical string) and `ActionKey.From(IAction)` produce a canonical string with subject-oracle keying for hand cards and instance-`Id` keying for board permanents/targets
- [ ] `ActionKey` collapses all fields into a single sorted `Canonical` string (no `ImmutableArray` in the record's equality surface); `IAction` is NOT made `IEquatable`
- [ ] `MctsStrategy : IStrategy` runs a fixed-iteration search on `PerformPrioritizedAction` and returns the robust child's action (max `VisitCount`); other callbacks delegate to a default policy
- [ ] Selection uses the availability-aware UCB `W/N + C·sqrt(ln(Available)/N)` with `C` from `MctsOptions`
- [ ] Expansion applies a move via a cloned `GameJudge`, advances to the next prioritized decision, and creates the child
- [ ] `PlanningStrategy` implements record-then-rollout: follows the tree policy on the searched player's callbacks, records the path, then hands off to `RandomStrategy` rollout on reaching an unexpanded node
- [ ] Rollout installs `RandomStrategy` (derived RNG) into both slots and loops `ExecuteNextTurn` to terminal or `TurnCap`
- [ ] Terminal scoring: win = 1.0, loss = 0.0, `HasError` = 0.5 (increment a spoiled-rollout counter); cap scoring via `Evaluate` clamped to (0.05, 0.95)
- [ ] `Evaluate` = logistic of `WLife·ΔLife + WBoard·ΔBoard + WHand·ΔHand` over `LogisticScale`, root-player perspective; `boardScore` sums (power + toughness) of a player's creatures
- [ ] `MctsOptions` config record: `Iterations`, `ExplorationC`, `TurnCap`, `MaxTurnGuard`, `WLife`, `WBoard`, `WHand`, `LogisticScale` with the documented defaults
- [ ] Backprop increments `VisitCount`/`TotalValue` on the path and `AvailableCount` for every legal edge at each visited node
- [ ] `MctsStrategy` uses ONLY the deep clone (perfect-information); determinization is out of scope for this task
- [ ] Sanity test: `MctsStrategy` (default options) vs `RandomStrategy` over paired seeds wins ≫ 50% on the current pool; the spoiled-rollout counter is ~0
- [ ] Isolation test: a search leaves the live tabletop unmutated (all mutation happens on clones)
- [ ] Existing tests pass

## 4. Implementation Guidance

- **Re-entrancy:** the search is invoked from inside a live `PerformPrioritizedAction` callback; it must operate entirely on clones with their own derived RNG so the suspended live game is never touched.
- **Rollout policy reuse:** `RandomStrategy` already exists — install it into both cloned player strategy slots for simulation. Do not reinvent a rollout policy.
- **Robust child, not max value** for the final returned action.
- **Values are single-perspective** (root player); there is no sign-flipping because only the root player's nodes exist in this slice.
- **Apply-by-key:** when expanding/descending, map the chosen `MoveKey` back to a concrete legal `IAction` from `FindLegalActions` on the clone (oracle-keyed subjects bind to any matching instance).
- **Turn-cap is cost control**, not correctness — decking already guarantees termination. Keep `MaxTurnGuard` as defense against a non-advancing engine bug.
- **Diagnostics:** surface the spoiled-rollout count; a nonzero fraction indicates a clone/engine bug (cross-reference the TASK_0602 Id-stability criterion), not a tuning problem.
- **Contract prerequisite:** if `ISource` is not yet on `IAction`, either land that small contract change first or derive the subject from `Target` as a temporary measure (documented as fragile in the design).
- Keep the searcher pluggable behind `IStrategy` so `TASK_0702` (determinized clone) and `TASK_0703` (combat nodes) extend it without a rewrite.
