## 2. Problem

With a recorded master seed (`TASK_0601`) and a canonical event stream (`TASK_0603`), a game can be reproduced by re-running from seed plus config. This task builds the replay artifact and the seed-replay runner, plus a validation hash that turns replay into a continuous determinism and regression check.

## 3. Acceptance Criteria

- [ ] A replay artifact type captures: schema version, engine version (git sha), master seed, `GameConfig`, and the optionally persisted event-stream JSONL
- [ ] A seed-replay runner reconstructs a game from master seed plus `GameConfig` and produces the identical event stream
- [ ] The regenerated event stream is hashed and compared to the stored hash; a mismatch is reported as a determinism or regression failure with the first divergent event
- [ ] Seed and config are always persisted; full JSONL persistence is opt-in (debug flag or on assertion or crash)
- [ ] A test round-trips a game: simulate, capture artifact, seed-replay, assert the hash matches

## 4. Implementation Guidance

- Stamp engine version from the build (git sha or assembly info); it marks the fidelity boundary — cross-version replay is best-effort.
- The hash covers the ordered event stream; `TASK_0602` events are already free of wall-clock noise.
- Reuse the JSONL sink for capture; the runner just re-drives `GameSimulator` with the recorded seed and config.
- On mismatch, walk both streams and report the first differing event and its request key.
